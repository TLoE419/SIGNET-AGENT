# SIGNET Desktop Workbench

A team-developed Electron desktop application for managing the six stages of the official SIGNET analysis workflow: data import, stage execution, status and logs, output validation, and official R Shiny visualization.

The desktop control layer uses Node.js; the official Python and R scientific code remains in the Linux scientific computing environment. There is no local Python HTTP control service.

## Getting Started with Development

Install Git and Node.js 24 LTS (minimum version: 22.12.0, with npm). From the root of your project checkout, run:

```sh
bash tools/setup-dev.sh
cd desktop
npm start
```

The setup script downloads the pinned version of the official code, installs the locked desktop dependencies and the Electron executable, and runs the standard tests. It does not download large scientific containers, start a virtual machine, or run an analysis. The initial setup requires an internet connection.

For the complete manual steps, platform-specific limitations, testing, and scientific computing environment setup, see the [Installation Guide](docs/INSTALL.md).

## Validation

```sh
cd desktop
npm test
```

The standard tests use small synthetic datasets generated by the code. They do not require the official code, a VM, scientific containers, or historical analysis results, and they do not perform scientific computation. Passing these tests validates only the control and result-checking logic; it does not demonstrate that the official scientific workflow has run successfully.

An edge-by-edge comparison against actual historical simulation results is available as an optional test:

```sh
cd desktop
npm run test:scientific
```

This test requires existing reference results to be prepared separately; they are not included in the repository. It fails explicitly if the required data is missing. It only reads results and does not submit new computation.

## Official Source and Installation Boundaries

Official source: https://github.com/signet4grn/SIGNET

Pinned commit: `bed55b3e121de0edf5fd43da683dc59850ff82d3`.

`tools/download-official.sh` downloads the code into the ignored `official-signet/` directory. If an existing copy has a different version, a different source, or local modifications, the script stops and preserves the existing files. The downloaded official code retains its license files. This repository does not include that copy or change the licensing of the official code.

The current scientific execution interface still connects to an existing local Linux VM. The university HPC environment is not yet connected; installing the desktop development environment does not install the complete scientific analysis environment. Packaging is currently configured only for Apple Silicon macOS, and the application is not yet signed or notarized. Desktop execution on other platforms has not been validated.

The official sixth stage requires `official-session.RData` to be generated and validated before Shiny can be opened through a restricted SSH tunnel. This is the official visualization, rather than the former custom results page. Closing the desktop application cleans up the visualization services it owns; independent analysis processes that have already been started continue running.
