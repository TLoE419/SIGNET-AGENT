## Visible flow

In formal Local result packages, authorize an existing prepared source with signet-package.json, inspect/register, choose a ready artifact and save selection. **Choose private folder and export selected original** opens the native directory picker, then runs the actual bounded copier in the existing worker. Only the selected original bytes are copied, named `<artifactId>.txt`; no preview-derived scientific output is generated. Existing target names are refused. The original plan-review buttons remain plans.

The UI displays actual result status, true/false/unknown written flag, known temporary bytes and each confirmed filename/bytes/SHA256. Partial/uncertain responses remain explicit. Science remains unknown. One last public request (package ID/hash, artifact IDs, request ID only) is stored in localStorage for recovery; no path, owner, root identity or grant is persisted in the renderer. Reload reads **historical** receipts only and labels them as such. **Reauthorize and reconcile last export** opens a new native picker; no destination authorization survives main restart. Pick the same original directory to reconcile the same intent/inode. A different directory conflicts rather than silently redirecting. Cancelling a fresh request writes no export state/targets; cancelling an existing request preserves true historical receipts and marks noNewWrites.

## Trust boundary and lifecycle

`desktop.packageExport` accepts exactly packageId/packageHash/artifactIds/requestId, with a 16 KiB cap, unique 1–32 IDs and bounded tokens. `packageExportStatus` accepts requestId only. No generic invoke or Service-call entry is exposed for export. Main validates exact current webContents/mainFrame/URL, formal mode and captured generation; navigation and every mode change invalidate live grants. Queued old-generation calls cannot open another picker or mint a grant. Completion after revocation preserves known receipts rather than claiming zero side effects.

Main prepares a current registered package through the real worker and accepts **only the native directory result**. ExportBroker binds a 60-second in-memory grant to a stable request-derived ID, stable runtime Operations owner, package/hash, filenames, destination/root+parent inode, captured sender/frame/mode generation and expiry. Public request keys are normalized so object property order does not change intent identity. The host rejects runtime tree overlap, noncanonical/symlink paths, other-user/group-writable ancestors, foreign ownership, nonprivate destination permissions and ACL write/delete grants. On macOS it reads bounded directory ACL metadata using fixed `/bin/ls -lde` argv (no shell), 32 ancestor/2048-character path cap, 3-second timeout and 64 KiB output cap. This is conservative host admission, not an ACL editor or arbitrary command bridge. Destination must exist, belong to the current user and be mode 0700; immediate parent must belong to the user. The host never changes existing folder permissions.

Service uses private worker message types to prepare/execute/read export history. Worker invokes the accepted Exporter with the current PackageIndex. On **each** destination resolution it sends a correlated private query to main; replies bypass the serial worker queue to avoid a deadlock. Main rechecks live frame/generation/expiry/protected directory identity and returns a private grant only to the worker. No destination path/grant enters a renderer request or result. Source authority still comes from the normal SourceBroker native-source path; it is not injected into hidden normal-main tests. Grants are removed after completion and invalidated at mode/navigation/quit; limits are 128 live grants and the executor's existing finite journal limits. Query timeout is 5 seconds, total export response timeout 120 seconds; after a timeout inspect the same request's historical receipt rather than inventing a new ID.

Accepted executor behavior remains byte-identical: source/index/export-state/destination two-way isolation (including V-A5-EXPORT-01), no overwrite, bounded full-byte/hash/stat checks, exclusive staging/fsync/readback, same-inode reconciliation, per-file partial/unknown truth flags and unknown-lock refusal. Stable IDs permit explicit cold reauthorization, not stale-token reuse. Status alone never proves current file presence or authorization.
