# S3-M local registry and finite plans

Contract `SIGNET-P3-X3-J4-v1`, adopted from `SIGNET-P3-X3-J4-v1-proposed`. This module is not wired into main, preload, Store, Service, task-worker, transport or the renderer. It never connects, probes, transfers, submits, runs science or creates a GUI. All returned intents have `executeEnabled:false` and `status:unknown`; submission inputs additionally have `jobReady:false`, unknown S4 prerequisites and unknown submission authorization.

## Entry and eight methods

`const {Registry}=require('./registry.cjs')`; create with `{root, readDraft, readCapability, authorize, now?}`. The root must be an explicitly owned runtime directory, separate from source trees and original user data. Ports are trusted **local** authority/read-only seams, never frontend callbacks or remote executors. No network ports are accepted or invoked. Missing credentials or site values block only plans, not null configuration storage.

All methods are async and throw fixed `{code,message:code}` errors. Inputs reject unknown fields, array/prototype objects, invalid versions, unsafe numbers and implicit conversion; arguments are limited to 64 KiB. IDs are core-generated for new records. New saves use `expectedRevision:0`; updates include their ID and expected current revision. Existing versions remain immutable.

| Method | Exact arguments | Result |
|---|---|---|
| profileSave | `{manifest,expectedRevision}` | `{profileRef,status:configured,authentication:unknown,transferReady:false,jobReady:false}` |
| profileDelete | `{profileRef,expectedRevision}` | recoverable soft archive; any resource, current/stale/historical binding or frozen intent referencing the profile blocks deletion |
| resourcePlanSave | `{plan,expectedRevision}` | `{resourceRef,status:configured,jobReady:false}` |
| bindingSave | `{binding,expectedRevision}` | `{bindingRef,status,transferReady:false,jobReady:false}`; one binding lineage per draft |
| bindingLoad | `{draftId}` | separate bounded draft view, binding and derived configured/stale status; never latest rebinding |
| profileCheckPlan | `{profileRef,endpointId,requestId}` | frozen nonexecuting probe intent with strict background policy |
| transferPlan | `{bindingRef,direction,sourceTokens,destinationRootId,relativePaths,requestId}` | frozen upload/download plan; no transfer |
| submissionPlanInput | `{bindingRef,stagePlanHash,requestId}` | frozen J4 input; no submit or jobReady |

References have exact `{<type>Id,revision,contentHash}`. `resourceRef` specifically uses **resourcePlanId**, capability refs use **snapshotId**, and draft refs use **draftId**. This spelling is an explicit proposal mapping, not an existing S2 bridge. `contentHash` is SHA256 of canonical JSON with recursively sorted object keys and original array order, UTF8; only finite JSON values are accepted. Registry hashes cover saved configuration content, not IDs/revision/timestamps. S1's existing hash algorithm and bytes are not changed.

Profile content: `{schemaVersion:1,profileId?,kind,name,endpoints,roots,storageMappings}`. Kind is hpc3 or local-vm. Endpoint fields are exactly `{endpointId,role,host,user,port,sshAlias,authRef,hostKeyRef}` with null unknown values; login/transfer/compute roles are distinct, no host/port/account/root defaults. Root fields: `{rootId,role,endpointPaths,access,canonicalEvidenceRef,permissionPolicy}`; role inputs/workspace/outputs/tools/container; access read/write/read-write; permissionPolicy preserve-destination-group or unknown. Paths are explicit UNIX absolute roots, no traversal/control characters; distinct role roots cannot have identical endpoint paths. Mapping fields: `{mappingId,rootId,endpointIds,storageIdentityRef}`. Same path spelling alone proves nothing.

Resource content: `{schemaVersion:1,resourcePlanId?,profileRef,account,partition,qos,cores,memoryMiB,walltimeSeconds,capabilityRef}`. Values may be null unknown; numeric values must otherwise be positive safe integers. Unit helpers `memoryMiB(value,'GiB')` require an exact positive integer result; 1.5 GiB = 1536 MiB. `walltimeSeconds('HH:MM:SS')` strictly parses 2–5 hour digits and minute/second below 60; 00:01:30 = 90. Unspecified GB is rejected. Plans check fresh site capability allowed values and upper bounds, never VM defaults. Human submission approval remains an additional S4 gate and is not granted here.

Binding content: `{schemaVersion:1,bindingId?,draftRef,inputValidationRef,profileRef,resourceRef,rootSelection}`. Nullable refs/root selection preserve unknown configuration. Resource must reference exactly the same profile version. Selection has exact `{inputRootId,workspaceRootId,outputRootId}` mapped to permitted profile roles. The binding is a sidecar, never added to S1 content or sent to draftSave. A changed draft/profile/resource invalidates new plans; explicit CAS rebinding is required.

## Trusted injected local ports

- `readDraft(draftId)` returns only `{draftId,revision,contentHash,validationRef?,inputManifestHash?}`, or null. The future adapter must obtain exact S1 bytes/validation/source status without exposing private paths. If a binding includes validationRef it must match this read. Binding saving reads draft before and immediately before committing; plan generation rechecks draft. This is a detection boundary, not a cross-registry atomic transaction.
- `authorize({kind:'handle',handleKind:'auth'|'host-key',ref})` returns `{ref,handleKind,authorized:true}` only for a core-held authorized opaque handle. Saving never reads actual secrets. Any unregistered handle is refused.
- `authorize({kind:'endpoint',profileRef,endpointId,authRef,hostKeyRef})` returns finite `{host,user,port,sshAlias,authRef,hostKeyRef,ownerIdentityRef,jumpHosts:[],capabilityRef?,endpointId?,role?}`. The tuple must match the profile. This initial module deliberately rejects all jump hosts and unknown SSH options; future supported jump routing needs a separately reviewed finite contract. No automatic host-key acceptance; BatchMode and StrictHostKeyChecking remain yes.
- `readCapability(snapshotRef)` returns a trusted immutable snapshot, or null. It includes snapshotId/revision/contentHash/profileRef/endpointId/checkedAt/expiresAt/authentication/reachability/environment/hostKeyRef/ownerIdentityRef/rootAccess/storageMappings/resources/artifactHashes/inputManifestHash/complete. Hash covers the whole snapshot except contentHash. Time checks require checkedAt <= now < expiresAt, duration <= 1 hour; equality at expiry is expired. Authentication must be authenticated, reachability/environment verified. The snapshot is endpoint-specific. Transfer uses the authority's transfer endpoint capabilityRef; submission uses resourcePlan's login snapshot.
- Each rootAccess entry has `{canonicalPath,storageIdentityRef,symlinkSafe:true,read:boolean,write:boolean}`. The path must equal the configured endpoint root. A storageMappings entry has `{storageIdentityRef,endpointIds,verified:true}` and must match the selected profile mapping, not just path text. Resource evidence contains accounts/partitions/qos and maxCores/maxMemoryMiB/maxWalltimeSeconds. Tool/container artifact hashes and a complete inputManifestHash are required for submission input.
- `authorize({kind:'source',token,direction})` returns `{token,direction,root,relativePath,sha256,bytes,symlinkSafe?,localDestinationRef?}` for the precise previously authorized file/selection. Upload checks existing actual local file, every current path component, canonical root, no-follow leaf descriptor, stable file metadata and bounded SHA256. Download requires remote selected-root evidence and a core-authorized localDestinationRef; the module never chooses a local destination path. Sources and endpoint authorization are reread immediately before an intent; revoked/changed evidence rejects the plan. Ports must give immutable snapshots and must report current source changes, never return an old fingerprint as fresh evidence.

Limits: <=3 endpoints, <=8 roots/mappings, <=128 selected files, <=64 MiB/file, <=256 MiB/plan, <=512 frozen request intents, <=4 MiB registry file. Array/string limits are module bounds, not university policy. Local authorization failures and raw I/O errors return fixed codes without secrets/private paths.

## Authority recheck correction (S3-V-01 / S3-V-02)

Before writing a transfer or submission intent, the module finishes capability/draft reference checks, then rereads the finite authorizations. Source comparison includes token, direction, exact authorized root, relativePath, SHA256, bytes, symlinkSafe and localDestinationRef; changing content-independent root/destination scope is rejected too. Download still requires a safe root and a main-selected destination handle. A missing/revoked source grant is denied, not accepted as an old fingerprint.

Endpoint comparison includes configured endpointId/role, host/user/port/sshAlias, authRef/hostKeyRef/ownerIdentityRef, jumpHosts and the effective capabilityRef (explicit grant ref or existing resource fallback). Optional endpointId/role declarations normalize to the configured values; absent/null optional source fields normalize to null. Equivalent representations do not create false drift. No arbitrary volatile metadata is added to this closed contract. A supplied endpointId/role must agree with the configured endpoint.

Initial endpoint/capability results are copied and source scope is captured in a new scalar snapshot before later awaits. An authority that mutates its previously returned object cannot rewrite the initial comparison evidence. Both transfer and submission recheck their endpoint after the final capability read; transfer also rereads every source scope. Changed/revoked authorization aborts without adding an intent or rewriting previous intents. Method names, schemas, S1/S2 source and executeEnabled=false remain unchanged.

These separate port reads are not an atomic transaction with an external authority or a future actual executor. Authorization can change again after a successful read; actual-effect integration still requires core-owned current authority/descriptor checks or an equivalent claim at its own boundary. The current module continues to produce nonexecuting plans only.

## Concurrency, persistence and later O2 integration

A single runtime registry contains profile/resource/binding versions and frozen request intents; one exclusive local lock covers CAS, unique-draft binding and all reference checks. Contention returns io_conflict, no retry or stale-lock removal. Writes use a 0600 temporary file, fsync, atomic rename and directory fsync; new directories are 0700. No old profile versions or referenced history are removed. Soft archive retains original versions, recoverable by a separately authorized repair; no restore API is implied.

Same requestId with identical input and complete plan hash returns the same persisted **intent ID**; different input/plan is operation_conflict. Lost response/restart remains unknown. These intent IDs are not S2 operation IDs or remote jobs. Subsequent S2 integration must map frozen binding/profile/resource/capability refs, rootMappingHash/inputManifestHash/operationHash into the final O2 operation identity including analysis/attempt/owner/revision. Do not replace frozen refs with latest; remote zero/multiple-candidate reconciliation, actual executor claims/cancellation and submission authorization are **not implemented in this pure module**. Recheck all references, authorization, root/storage evidence and file identities immediately before any future effect.

Current component/symlink checks plus pre/post metadata detect visible replacement; pure Node path checks do not provide an unconditional race-free openat guarantee against a malicious concurrent ancestor replacement. The future actual-transfer executor must use main-owned descriptors or an equivalently protected/sandboxed root, and must recheck remote canonical roots. No transfer is permitted by these plans alone. Likewise cross-S1 registry races are detected by repeated reads, not claimed exactly-once or globally atomic.

## Reproducible author tests

Run `node --test --test-reporter=tap desktop/core/s3/test-module.cjs` from the clone. Only Node builtins are required; no dependency installation, GUI, SSH or science. Fixtures are generated beneath this task's owned S3-build-evidence/runtime. Tests instrument attempted child-process/network calls (including exceptions) and require zero external effects. All hosts, capabilities, credentials handles and data are synthetic `.invalid`/owned fixtures; tests are not station or scientific acceptance. V1 exercises original S1 Drafts save/validate with unchanged source and compares bytes, without rerunning the old full suites. Independent verify and polish remain separate stages.
