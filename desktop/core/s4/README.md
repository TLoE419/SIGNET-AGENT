# S4-M finite graph/resource planning

Contract `SIGNET-J4-graph-v1` adopts the planner graph proposal. Only this directory is new; S1/S2/S3 and shared core/UI remain unchanged. All functions accept local immutable records or bounded text. No SSH/network/probe/Slurm/R/scientific/GUI executor exists. `launchReady` and `executeEnabled` always remain false, including plans with successful synthetic preflight. This is not an O2 operation adapter or actual scheduler execution.

## Public entry points

Import `planning.cjs`. The four main proposal seams are `stagePlanBuild`, `resourceRenderAndParse`, `graphExpandAndCheck`, `submissionSnapshotParse`. Bounded helpers are `timeFormats`, `parseTime`, `resourceReadback`, `cancellationPlan`, `retryPlan` and local `GraphLedger`. Errors are fixed codes/messages; raw filesystem or remote errors are not returned.

`stagePlanBuild(input, evidence=null, now=Date.now())` accepts exact keys:

- schemaVersion=1, analysisId/attemptId/owner, stage genotype/expression/adjustment/ciseqtl/network/visualization, explicit mode single-stage-batch/network-controller-batches/network-allocation-steps, nboots (0–100).
- refs: exact draftRef/bindingRef/profileRef/resourceRef/capabilityRefs plus o2 `{version,commit}`. S3 resource references retain resourcePlanId, capability references snapshotId. No latest or override.
- official `{commit,sourceHash,containerHash}`, rootRefs `{workspace,tools,container,inputs,outputs}` with exact `{rootId,contentHash}` or null unknown.
- controllerResource, phaseResources `{phase1?,phase2?}`, approvalBudgetRef. Optional plannedGraph must match the finite core skeleton; cyclic or alternative/mixed topology is rejected. Dynamic children are registered through actual generated manifests, not arbitrary frontend DAGs.

Output contains core planId/revision/planHash, frozen content, bounded graph with pending batch-job (F) or allocation-step (T), null dynamic count, blockedIssues and preflightReady. Hash covers the entire execution content, exact reference versions, approval budget and preflight evidence hash/state. Metadata cannot be widened independently. Unknown/null site/container/budget evidence saves a blocked plan; preflight does not grant launch approval.

The separate **trusted local evidence argument** is not frontend data and performs no queries: resolvedRefs; resolvedResources (<=8 exact `{resourceRef,profileRef,cores}`); resolvedRootRefs/resolvedOfficial; rootMappingHash; placement/endpointRole/nestedSubmission/stepAllocation/containerMounts/schedulerVersion/mappingVersion/chronOver24h/controllerBudgetIncludesWait; checkedAt/expiresAt; approval and resourceLimits. Values come from the future accepted P3/O2/site authority adapter. Null/missing values block applicable plans. Exact profile, per-job P3 version/CPU count, root and source drift block preflight. Freshness requires nonnegative safe-integer times and capability checkedAt <= preflight checkedAt <= now < expiresAt, with both observation ages and the capability validity duration bounded to 1h. The capability observation time, preflight time, expiry and fixed maxAgeMs policy are part of the hashed preflight state. GraphLedger.reserve reads its clock once and rechecks that state inside the transaction before creating/reusing any intent. Expiry equality, future observations, invalid clocks and excessive age/lifetime fail capability_stale without changing ledger bytes. Historical plans missing the new observation fields remain readable but cannot reserve new intents; no records are deleted, references rebound, or approval migrated automatically. A new complete trusted preflight must produce a new hashed plan. Compute-allocation placement, supported controller submission or step allocation, trusted mounts and explicit controller wait/preparation/summarization budget are separate requirements. No login-node compute, transfer-node submit, nohup or direct SSH fallback is introduced.

Approval has budgetRef plus exact analysisId/attemptId/owner/stage/mode/sourceHash and positive maxSchedulerJobs/maxConcurrentJobs/maxConcurrentCPUs/maxConcurrentMemoryMiB/maxCPUSeconds/maxMemoryMiBSeconds/maxControllerSeconds. resourceLimits separately has maxCPUs/maxMemoryMiB/maxWalltimeSeconds. Synthetic limits are never campus policy or human approval.

## Resource mapping and text

A job resource has exact resourceId/revision/role/p3Ref/p3Cores/mappingVersion/layout/account/partition/qos/nodes/ntasks/cpusPerTask/memoryMode/memoryMiB/walltimeSeconds/paraFlyConcurrency. Role is controller/single-stage/network-child/network-step. CPU count is explicit ntasks*cpusPerTask, equal to the referenced P3 cores; legacy-ntasks means C tasks x1 CPU, single-process means 1 task xC CPUs. Neither is chosen implicitly; ParaFly concurrency must fit. Nodes are restricted to one in this version, not a campus-wide default. Memory is positive integer MiB, exactly per-node or per-cpu; total per-cpu memory multiplies requested CPUs. Account/partition unknown blocks preflight; qos=null explicitly means no QoS request, not a verified default privilege.

`timeFormats(90061)` returns official `25:01:01` and Slurm `1-01:01:01`; `parseTime(text,'official'|'slurm')` round-trips strictly. Zero/negative/nonfinite/bool and days-format sent to the official three-column parser are rejected. Official chron acceptance above 24h remains capability-gated, not inferred from successful formatting.

`resourceRenderAndParse({resource,mode:'render'|'inspect',stage,scriptText?,originalTemplateHash?})` renders fixed limited directives and a fixed six-flag/ParaFly command or inspects a bounded readonly script. Unknown/duplicate/conflicting SBATCH options, substitution and unresolved directive values are rejected; missing required memory/account/task settings are not-applied. Generated fields are separate from submitted/observed (unknown). ParaFly in a controller/single-stage is only mapping-plan-only unless present in the actual script. Step scripts have no SBATCH allocation: an explicit srun argv plan is returned, and step allocation remains not-applied until independently observed.

The patchPlan targets only `.ori-before-generator` in a **new attempt run copy**, stores original/generated hashes, and is `applied:false`; it never runs or rewrites the official generator, R algorithm, config or any file. Missing originalTemplateHash remains explicit. The renderer uses fixed relative run-copy paths (`./official`, `./container.sif`, `./params.txt`), not frontend shell/path input. Final real orchestration must bind these paths to accepted roots, verify original/config/template/subscript/params hashes and actual argv after generation. Rendering is not evidence that an actual submission used these resources.

`resourceReadback({resource,observed,supportedVersion,allocationLimits})` consumes a normalized, authoritative scheduler snapshot: Account/Partition/QOS/NumNodes/NumTasks/CPUsPerTask/MemoryMode/MemoryMiB/TimeLimit/ReqCPUs/AllocCPUs/ReqMemoryMiB/AllocMemoryMiB. Unsupported version is unknown. Requested totals must match; actual allocation must fit explicitly approved maxAllocatedCPUs/maxAllocatedMemoryMiB, never silently accept rounding or over-allocation. A mismatch blocks continuation. This does not parse an unverified HPC installation or perform readback.

## Dynamic manifests, CAS and bounded reservations

`graphExpandAndCheck({plan,ledger,expectedRevision,generated})` is a pure reducer. Generated items have fileId/phase/paramsText/paramsHash/subscriptText/subscriptHash/units/geneCount. Text SHA256 must match actual bounded bytes. Params must be nonempty, each command index maps exactly once to bootstrapIndex (0..nboots) and inclusive geneRange; a batch can contain several bootstrap units. Subscript must match this finite resource renderer. Same filename in different phases is distinct; duplicate phase/name, empty tails or changed script/resource text are rejected. Each expansion is limited to128 files, total256 batches, 64KiB per text and1MiB arguments. The future adapter must capture actual generated complete manifests; this module does not run R or infer their count from nboots.

`new GraphLedger(ownedRuntimeRoot,plan,nowFn?)` adds local persistence around the reducer. `.expand({expectedRevision,generated})`, `.reserve({expectedRevision,requestId,nodeId,phase1Proof?})` and `.stopExpansion()` use a short exclusive filesystem lock and one <=4MiB atomic ledger. Files0600/new directories0700, fsync/rename/directory fsync; contention io_conflict, never steal unknown locks. Original and S2/S3/S4 source roots and visible symlink roots are refused. The caller is core authority supplying an owned runtime, not a frontend path selector.

F budgets count one controller batch and every actual child batch, parent wait cost included; concurrent peak uses the larger phase, total CPU/memory time sums parent and all children. T counts one scheduler allocation, with steps constrained by parent CPU/memory/time; resources of all registered steps in a phase are conservatively summed. This version has no wave/overlap optimization: a larger simultaneous manifest is rejected even if a future scheduler could serialize it. Total future expansion remains unknown. Each intent reservation is rechecked atomically against the whole known graph and freezes full plan/node/resource/script/params/source/owner refs. This is a **local plan reservation**, not a scheduler reservation or submission.

Same request+payload returns one persistent intent ID and submission-unknown after loss/restart; another node or a new request for the same logical node conflicts. No intent is an O2 operation/job. Phase2 reserve requires trusted complete-generation/output verification tied to planHash and exact phase1 manifestHash, with outputManifestHash; phase1 is then sealed against late expansion. Barriers depend on every registered actual phase child. Controller-parent edges are logical ownership/start relationships, not instructions to place child jobs after parent termination via sbatch dependency.

## Submission/history, cancellation and retry

`submissionSnapshotParse({format,owned,now,stdout?,stderr?,exitCode?,snapshot?,maxAgeMs?,submitWindow?})` supports strict `parsable`, `sbatch-text` or normalized `history`. Stdout/stderr stay separate, bounded64KiB; only exact Slurm acknowledgement syntax is accepted, never arbitrary trailing digits or PID text. owned keys bind cluster/jobId/submitTime/user/workDir/analysisId/attemptId/owner/nodeId/phase/paramsHash/subscriptHash, and step keys add parentJobId/stepId (jobId=parent allocation ID). SubmitTime is normalized UTC ISO with milliseconds, not guessed from a shell PID.

Before an actual job/time is known, owned.jobId/submitTime can be null: an acknowledgement returns an unverified candidate, no fabricated full scheduler key. History matching then requires an exact <=1h submitWindow and full remaining ownership/source scope. Batch/controller keys have neither parentJobId nor stepId; allocation-step keys require both, with exact parent and step values. Pending reconciliation requires identical presence of these fields before comparing values, so extra, absent or different step identity cannot attach to another job family. Half-present identities are rejected as lineage_mismatch; non-JSON undefined values are rejected by the inherited canonical schema validator. For valid snapshots, zero/multiple/stale candidates remain unknown/resubmit=false. One exact candidate may recover its actual key and monitoring state. History records are `{key,state,exitCode,outputVerification}` with checkedAt; default maxAge60s, capped5min. These are authoritative owned snapshots supplied by the later adapter, not a global queue scan. COMPLETED/0:0 is verifying unless independent output proof binds the exact keyHash and manifestHash; an exit0 alone is never scientific success.

`cancellationPlan(input,authority)` needs confirmed explicit keys plus full frozen authority `{planHash,ownedKeys,now}`. It rejects foreign attempts/job IDs, stops future expansion first, and emits only selected owned keys; all frozen keys must have fresh terminal evidence plus controller-stop/no-residual evidence before overall cancelled. Omitted or active children keep cancelling, including when the parent stopped. It never sends scancel or cancels a whole user/queue. Authorities/proofs are core-held records, not boolean assertions from the UI.

`retryPlan` accepts only full-required-stage, different new attempt, purge=false; preserves previous successful outputs and reports network workload unknown until generated manifests. stage2-only, subset and old-run reuse/purge are refused. Actual isolated attempt creation and execution remain later integration work.
